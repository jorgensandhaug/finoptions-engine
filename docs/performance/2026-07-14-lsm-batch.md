# LSM batch performance checkpoint: 2026-07-14

This is a reproducible local checkpoint, not a cross-machine guarantee. The compared paths use the
same financial estimator and row-level random identity, but their timed setup differs: scalar plans
are prebuilt and prevalidated, while the batch validates and constructs every row inside timing.

## Environment

- Apple M4 Pro, 14 CPU cores, 48 GiB unified memory
- macOS 26.2, arm64
- Rust 1.97.0, `--profile bench` (`thin` LTO, one codegen unit)
- `uv` 0.11.28

## Throughput workload

The Criterion workload prices fixed-strike Bermudan calls with 150 base intervals, one exact cash
dividend at year fraction 0.5, 500 policy-fitting paths, 500 independent evaluation paths, and a
checked degree-four continuation regression. Contract rows vary spot, strike, rate, volatility,
and cash amount. The scalar comparator is deliberately advantaged by constructing its financial
plans before timing; the batch path validates and constructs row plans inside the timed request.

| Execution | Rows | Mean elapsed | Throughput |
|---|---:|---:|---:|
| Batch, contract-parallel, 4 threads | 256 | 356.21 ms | 718.68 contracts/s |
| Repeated scalar, path-parallel, 4 threads | 256 | 821.09 ms | 311.78 contracts/s |
| Batch, serial | 256 | 1.4357 s | 178.31 contracts/s |
| Repeated scalar, serial | 256 | 1.4280 s | 179.27 contracts/s |

The isolated four-thread Criterion intervals were 717.90–719.45 contracts/s for the batch and
307.72–314.66 contracts/s for repeated scalar calls. At this workload, outer contract parallelism
was about 2.30 times as fast as repeated inner path parallelism, and the batch scaled about 4.03
times from one to four threads. These ratios describe this machine and workload only.

Reproduce the focused release measurements with:

```shell
cargo bench -p finoptions-lsm --bench lsm_batch -- '4t/256$'
cargo bench -p finoptions-lsm --bench lsm_batch -- '1t/256$'
```

## Scratch-memory change

Serial seeded simulation previously materialized a complete path-major matrix before transposing
it into the required time-major output. Contract-parallel workers now use a fixed 32-path
path-major block and transpose each block directly into the final allocation. Random addresses,
path order, arithmetic order within each path, and every output bit are unchanged.

Fresh-process A/B probes of incremental process high-water RSS measured:

| Rows | Complete path-major scratch | 32-path scratch blocks |
|---|---:|---:|
| 32 | 11.3–11.6 MB | 6.0–7.2 MB |
| 4,096 | 15.1–15.3 MB | 8.1–9.5 MB |

The ranges are repeated observations rather than confidence intervals. High-water RSS is a coarse
process metric, but the direction is consistent at small and large row counts, and scratch now
scales with active workers rather than batch rows. Current public-API probes sustained about
684–691 contracts/s at 32 rows and 705–706 contracts/s at 4,096 rows on four threads.

Rebuild the native extension and reproduce the current 32-path side with:

```shell
just native release
uv run --no-sync python benchmarks/lsm_batch_memory.py --rows 4096 --threads 4
```

The recorded complete-scratch comparator used the identical source with only
`SERIAL_PATH_BLOCK = usize::MAX`, which makes one path-major block span the full population; it was
rebuilt in release mode and measured in a new process with the same command. That historical side
is a documented A/B procedure, not a separately retained executable or permanent feature.

## Profile-guided next work

A five-second macOS sample of the 256-row four-thread batch identified GBM exponential evaluation as
the largest CPU consumer, followed by LSM policy fitting and Philox random generation. Plan
construction was negligible. This justified evaluating a vectorized implementation without
changing the estimator, random streams, event schedule, or regression contract.

## Explicit Apple vector backend

The accepted macOS backend calls Accelerate vForce `vvexp` through the isolated audited wrapper in
`finoptions-accelerate`. It is explicitly selected and recorded; it is neither an approximation
toggle nor a fallback. Differential tests over exponents from -700 through 700 require at most one
ULP from Rust standard-library `f64::exp`. Complete LSM prices may differ more because a last-bit
path change can alter a fitted stopping decision, so they are checked by financial bounds and
backend-local reproducibility rather than cross-backend bit equality.

Five fresh release-profile processes priced 2,048 contracts at eight threads with 150 intervals,
500 training paths, 500 independent evaluation paths, and degree-four regression:

| Backend | Median elapsed | Median throughput | Median peak RSS |
|---|---:|---:|---:|
| `rust_std_f64` | 1.9979 s | 1,025.09 contracts/s | 51.4 MB |
| `apple_accelerate_vforce` | 1.4634 s | 1,399.50 contracts/s | 49.5 MB |

The vector backend increased median throughput by 36.5% and reduced median elapsed time by 26.8%
on this workload. One scalar observation was substantially faster than the other four; the median
avoids selecting either backend's best observation. Reproduce either side with:

```shell
just native release
uv run --no-sync python benchmarks/lsm_batch_memory.py \
  --rows 2048 --threads 8 --math-backend rust_std_f64
uv run --no-sync python benchmarks/lsm_batch_memory.py \
  --rows 2048 --threads 8 --math-backend apple_accelerate_vforce
```
